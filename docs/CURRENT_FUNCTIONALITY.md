# Актуальный функционал

Актуально на 2026-03-24.

`gitTrainer` уже работает как SPA для практики Git с backend на Spring Boot.

## Что доступно пользователю

- Каталог сценариев с фильтрацией по сложности и тегам, сортировкой по названию или сложности.
- Экран сценария с тремя зонами: навигация по сценарию, описание урока и панель практики.
- Просмотр контекста репозитория для сценария: ветки, коммиты, изменённые файлы, аннотации.
- Запуск тренировочной сессии для выбранного сценария.
- Отправка ответа в формате одной Git-команды.
- Получение результата проверки: `correct`, `partial`, `incorrect`, `unsupported`.
- Повторные попытки с retry-feedback, объяснением ошибки и поэтапным усилением подсказок.
- Экран прогресса: статус по сценариям, недавняя активность и рекомендация следующего шага.

## Что реализовано на backend

- API сценариев: `GET /api/scenarios`, `GET /api/scenarios/{slug}`.
- API сессий: `POST /api/sessions`, `POST /api/sessions/{sessionId}/submissions`.
- API прогресса: `GET /api/progress`.
- При старте сессии создаётся отдельный Git workspace в файловой системе.
- После каждой отправки ответа сохраняются попытка, результат валидации и событие прогресса.
- В ответах по сессии возвращается live-снимок workspace: текущие ветки, последние коммиты, состояние файлов, служебные аннотации.
- Есть два режима данных:
  - `postgres`: авторские сценарии, retry-feedback, validation specs и прогресс хранятся в БД.
  - `local-memory`: те же пользовательские потоки работают на fixture-данных и in-memory хранилищах.

## Валидация ответа

- Сейчас поддерживается только `answerType = command_text`.
- Реализованы rule-based проверки Git-команд.
- В текущем authored-наборе используются два типа валидаторов:
  - `git_command_probe`
  - `git_repo_state_probe`
- Для `postgres` доступен CLI validator с реальным выполнением проверки в подготовленном workspace.

## Что есть во frontend

- Маршруты: `#/catalog`, `#/exercise/<slug>`, `#/progress`.
- Переключение источника данных: `backend-api` или `local-fixture`.
- Предзагрузка деталей сценариев, обработка loading/error/empty состояний.
- Повтор отправки, перезапуск сессии и раскрытие следующих подсказок из UI.
